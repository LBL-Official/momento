# NBA Bot 001 — operations

Worker for FIRST78_67 (`nba-001`, policy `nba-001-v1`). It collects
production data, evaluates signals, and runs the hedge path in SHADOW. It
cannot submit an order.

The deployed build links no submission adapter. The source contains the
NBA order adapter, lifecycle, and reconciler, exercised on fixtures and the
Kalshi demo (`momento-nba-001 demo-exercise`). Production orders are
compiled out. Status: `research/vital/bots/nba-001/IMPLEMENTATION_STATUS.md`.

## What the worker does each tick (15 s)

1. Reads `controls.json`. Missing = off; malformed = paused.
   `full_stop` persists and exits 78. `emergency_exit` is journaled as
   blocked, because the emergency action is unresolved.
2. Every 300 s, discovers open `KXNBAGAME` events and records the series and
   per-market `exchange_index`.
3. For each game from 24 h before start: backfills 1-minute candles, reads
   the Kalshi `live_data` clock, and applies the FIRST78 up-cross (Q2/Q3 by
   clock, touch or cross of 78, top-out ceiling 85).
4. On a signal, refreshes the event, verifies the exact complement pair and
   route, and runs admission. Every hard blocker is listed. Blocked intents
   are journaled with the full blocker list.
5. Every 60 s, reads balance and positions with the GET-only production
   transport. A failed read is `UNREAD`, never `$0`.
6. Writes `status.json` atomically, appends to `journal.jsonl`, and prints a
   heartbeat line to the journal every fourth tick.

While no game is inside its 24 h window, the worker makes public reads
only on the 300 s discovery cycle. `feed_age_s` then climbs from 0 to about
300 and resets. It is not a stale feed. Per-game candles and the clock
start when a game enters its window.

## Modes

`live_data_only` collects only. `shadow` also runs signal, admission, and
the local hedge path. `live` is derived only when both live gates are set
and every blocker clears. No build can reach it today:
- The deployed build has no adapter.
- Source builds carry `PRODUCTION_ORDERS_NOT_COMPILED` and
  `FRACTIONAL_FILLS_UNSUPPORTED`.
- The contract has six `UNRESOLVED_OWNER_INPUT` fields.

## Demo exercise and host evidence

- `momento-nba-001 demo-exercise` needs `MOMENTO_KALSHI_SECRET_FILE`
  pointing at a **demo** secret. It places and cancels small orders on
  `external-api.demo.kalshi.co` only (the builder runs it after tests).
- `momento-nba-001 evidence` is GET-only on production. It reports tier,
  subaccounts, netting, allocation, shard cash, routing, and a fill-level
  fee comparison with hashed order ids. Run it once from a temporary copy
  with the NBA secret file; it never replaces the service binary.

## Build (throwaway ARM64 builder)

Do not cross-compile from macOS. Stage a tarball of `Cargo.*`,
`rust-toolchain.toml`, `apps`, `crates`, `strategies`, `config`, `deploy`,
and `research/vital/bots/nba-001` (exclude `target`, `.venv`, and
`apps/terminal-efficiency`) to `s3://…/m10/nba-001/src/`. On an AL2023
arm64 builder whose role can only read `src/` and write `build/`:

```text
deploy/nba001-arm64-build.sh /opt/src /tmp/nba001 <build_id>
aws s3 cp /tmp/nba001/ s3://…/m10/nba-001/build/<build_id>/ --recursive
```

The build script refuses any order-submission symbol in the worker and
runs the strategy, worker, and GET-only transport tests. Terminate the
builder and delete its role afterwards.

## Install

On the live host via SSM, as root:

```text
deploy/nba001-atomic-deploy.sh s3://…/m10/nba-001/build/<build_id>/ <sha256> live_data_only
deploy/nba001-atomic-deploy.sh s3://…/m10/nba-001/build/<build_id>/ <sha256> shadow
```

The script verifies every bundle checksum, installs the binary through a
`.new` rename, and keeps a `.bak` copy. It then requires a fresh
`status.json` heartbeat whose binary and contract digests match and whose
mode is the requested mode. It fingerprints `momento-live.service` (active
state, main PID, binary digest) before and after, and rolls back if that
fingerprint changes. `live` is refused.

The first install (2026-09-27) is recorded in
`research/vital/bots/nba-001/IMPLEMENTATION_STATUS.md` (build
`nba001-20260927T042347Z`, binary `9ef129e1…6789`).

## Observe

The desk reads the host over read-only SSM with a 20 s cache.
`status.json` is compressed with zlib and base64-encoded because SSM
stdout is capped at 24 KB. The heartbeat is fresh at 90 s or less.
`healthy` means running, fresh, and the process binary digest equals the
installed digest. `executing` is always false.

From a shell:

```text
systemctl status momento-nba-001
journalctl -u momento-nba-001 -n 20 -o cat
sudo -u momento /usr/local/bin/momento-nba-001 probe   # series, per-market index, account; funds_moved:false
```

## Stop

Write `{"full_stop": true}` to `/var/lib/momento/nba-001/controls.json`.
The worker persists and exits 78, and systemd does not restart it. Or run
`systemctl stop momento-nba-001`. Neither action affects
`momento-live.service`.

## Never

- Link a submission adapter without a resolved contract, verified routing
  and funds, and explicit owner approval.
- Move funds or issue a funding instruction before the market's shard is
  verified (`FUNDING_ROUTING.md`).
- Touch `momento-live.service`, `/usr/local/bin/momento-trading-engine`, or
  `VITAL_AWS_CONTROL`.
- Print the Kalshi secret.
